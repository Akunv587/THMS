## 简介
本文件聚焦THMS系统的采购与销售数据模型，围绕以下目标展开：
- 完整描述采购订单实体与字段、销售订单实体与字段的业务流程设计
- 深入说明采购入库与库存联动、销售出库与库存联动的机制
- 阐述订单明细表的设计模式、价格计算逻辑与折扣处理的数据结构
- 解释采购退货与销售退货的逆向业务流程数据模型
- 说明供应商、客户信息与订单的关联关系
- 提供完整的采购销售业务流程ER图与状态机设计
- 给出复杂查询与报表统计的SQL示例

## 项目结构
本项目采用分层架构：
- 领域模型层（Models）：定义实体、枚举、DTO等
- 数据访问层（DAL）：通过EF Core配置与仓储接口实现数据持久化
- 业务逻辑层（BLL）：封装业务流程、事务与库存联动
- Web层（Web）：控制器、视图与后台任务

## 架构总览
采购销售整体架构遵循“控制器→服务→仓储→数据库”的分层调用路径，关键业务在BLL服务中编排，涉及库存变动的操作统一通过库存交易记录落库，保证可追溯与一致性。

```mermaid
sequenceDiagram
participant C as "控制器"
participant S as "业务服务"
participant R as "仓储接口"
participant DB as "数据库"
C->>S : "提交采购订单/销售订单"
S->>R : "保存订单及明细"
R->>DB : "写入订单表与明细表"
DB-->>R : "返回成功"
R-->>S : "返回结果"
S-->>C : "返回响应"
Note over S,DB : "后续入库/出库由独立流程触发，并生成库存交易记录"
```

### 采购订单与明细（字段与流程）
- 采购订单主表关键字段
  - 单号、供应商、总金额、状态、创建/更新时间
- 采购订单明细关键字段
  - 商品、仓库、订购数量、已入库数量、单价、折扣率、行金额、备注
- 业务流程要点
  - 订单创建后进入待审核/待确认状态
  - 根据明细生成采购入库计划
  - 入库完成后更新明细已入库数量与订单状态

```mermaid
flowchart TD
Start(["开始"]) --> CreateOrder["创建采购订单"]
CreateOrder --> SetStatus["设置订单状态为待确认"]
SetStatus --> Confirm{"是否确认?"}
Confirm --> |是| PlanIn["生成入库计划"]
Confirm --> |否| Cancel["取消订单"]
PlanIn --> Inbound["执行采购入库"]
Inbound --> UpdateQty["更新明细已入库数量"]
UpdateQty --> OrderDone{"全部入库完成?"}
OrderDone --> |是| CloseOrder["关闭订单"]
OrderDone --> |否| WaitMore["等待剩余入库"]
Cancel --> End(["结束"])
CloseOrder --> End
WaitMore --> End
```

### 订单明细设计模式、价格计算与折扣
- 设计模式
  - 主从表结构：订单主表与明细表一对多
  - 明细维度：商品、仓库、数量、单价、折扣率、行金额、备注
- 价格计算逻辑
  - 行金额 = 数量 × 单价 × (1 - 折扣率)
  - 订单总金额 = 所有明细行金额之和
- 折扣处理数据结构
  - 折扣率字段位于明细行，支持按行折扣
  - 如需全局折扣，可在订单主表增加折扣字段并在汇总时应用

```mermaid

B --> C["累加到订单总金额"]
C --> D["校验总金额与明细合计一致"]
D --> E["保存订单与明细"]
```
