## 简介
本模块围绕“采购订单管理、采购入库、采购退货”三大业务主线，提供端到端的流程实现与数据联动。重点包括：
- 采购订单的创建、编辑、审核、关闭等状态流转
- 采购入库单生成与库存联动更新（含事务性保证）
- 采购退货处理与库存回冲
- 供应商结算与采购统计分析
- 与库存、财务系统的集成点说明
- 成本控制、供应商评估与采购优化的策略建议

## 项目结构
采购相关代码遵循分层架构：Web 控制器层调用 BLL 服务层，服务层通过 DAL 仓储访问数据库实体与枚举。关键文件分布如下：
- Web 层：采购订单、入库、退货控制器
- BLL 层：采购服务实现与接口
- DAL 层：采购订单仓储、库存仓储、库存交易仓储
- 模型层：实体、DTO、枚举定义

### 采购退货处理
- 业务流程
  - 基于订单或入库单发起退货申请
  - 审核通过后执行退货出库，回冲库存并减少应付
- 关键点
  - 退货数量不得超过已入库数量
  - 退货原因与质检结果记录
  - 退货完成后更新关联单据状态

```mermaid
flowchart TD
Start(["开始"]) --> CreateReturn["创建退货单<br/>选择来源(订单/入库单)"]
CreateReturn --> Validate["校验可退数量与原因"]
Validate --> Valid{"校验通过?"}
Valid --> |否| Reject["拒绝/退回修改"]
Valid --> |是| Approve["审核退货"]
Approve --> Outbound["执行退货出库<br/>回冲库存+记录交易"]
Outbound --> UpdateRelated["更新关联单据状态"]
UpdateRelated --> End(["结束"])
Reject --> End
```

## 故障排查指南
- 常见错误
  - 超入：入库数量大于订单剩余可入数量
  - 超退：退货数量大于已入库数量
  - 并发冲突：多用户同时操作同一订单导致状态不一致
- 定位步骤
  - 检查订单/入库/退货状态是否满足转换条件
  - 核对库存交易流水是否成对出现（入库为正、退货为负）
  - 查看事务日志与异常堆栈，确认是否中途回滚
- 修复建议
  - 在入库前预检剩余可入数量
  - 引入乐观锁或版本号字段避免并发覆盖
  - 对关键操作增加幂等键，防止重复提交
